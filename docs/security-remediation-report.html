The patch closes or mitigates the source-level defects identified in the audit and hardens the sample image defaults. SEC-01

Unauthenticated qconn remote execution

Network peer → superuser command execution
CriticalFixed

Issue

The default image included and launched bare qconn. QNX documents that the development service lets a client run applications as superuser and supplies no production authentication boundary.

Remediation

Remove qconn, pdebug, and devc-pty from the production IFS and startup path. Keep a commented lab-only recipe using -a -l behind an authenticated tunnel.

Why it works

Removing the binary and launch line eliminates the TCP execution endpoint. Local-only lab binding prevents direct network reachability; -a preserves ASLR for debug children.

Vulnerable base (abridged)images/rpi5.build
## REMOTE_DEBUG: gdb or Momentics
devc-pty
qconn
Corrected (abridged)images/rpi5.build
## qconn is intentionally disabled ...
# devc-pty
# qconn -a -l

CWE-306 · External reference: QNX qconn utility documentation.

SEC-02

Published account credentials and readable shadow data

Network login or local user → reusable account access and potential setuid escalation
HighFixed

Issue

The build started SSH, shipped setuid su, embedded documented root/root and qnxuser/qnxuser password hashes, and emitted /etc/shadow as mode 0644. Where the imported SSH/PAM defaults permit password login, the published user credential followed by the published root credential forms a network-to-root path.

Remediation

Lock both password fields with *, change shadow mode to 0600, and document unique per-device credential or SSH-key provisioning plus explicit SSH policy review.

Why it works

A locked field cannot authenticate with the published password through SSH, PAM, or su, and mode 0600 prevents ordinary users from harvesting password hashes for offline attack.

HighFixed

Issue

Remediation

Why it works

SEC-04

Fan read-offset underflow discloses stack memory

Stale offset + shorter value → oversized IOV
HighFixed

Issue

io_read() recomputed a short string, then subtracted an unchecked signed file offset into size_t. When the value shrank, the subtraction underflowed and exposed bytes beyond the stack buffer.

Remediation

Reject negative offsets, return normal EOF when the offset is at or beyond the produced length, convert only after validation, and cap the IOV to the actual remaining bytes.

Why it works

The subtraction now occurs only when 0 ≤ offset < length, so nleft cannot wrap and buf + offset remains inside the formatted buffer.

Corrected (abridged)fan/resmgr.c

    _IO_SET_READ_NBYTES(ctp, 0);

SEC-05

GEN/MAN SDMMC devctls cross message boundaries

Unchecked block length and NEXT cursor
HighFixed

Issue

Raw command loops trusted blklen and advanced to chained records without comparing headers or payloads with cam_devctl_size. Lower layers copied exactly that untrusted length.

Remediation

Track a byte cursor and remaining length, copy potentially unaligned headers locally, validate every header + payload, and limit a request to 64 chained commands.

Why it works

Every buffer passed to the device layer is now wholly contained in the devctl message; NEXT can advance only by a validated record size and cannot walk indefinitely.

SEC-06

ASSD response length overflows the caller buffer

Card-controlled length → heap overwrite and source over-read
HighFixed

Issue

The request was size-checked, but the two-byte length returned by the card was copied with a 512-byte cap—not the caller’s output capacity or the 510 bytes available after the wire header.

Remediation

Validate the fixed devctl header, request capacity, wire length 2–512, response payload 0–510, and destination capacity before copying. Return EMSGSIZE when output is insufficient.

Why it works

Both source and destination bounds are derived before memcpy; a malicious card can no longer choose a length that escapes either buffer.

Corrected (abridged)sim_assd.c

SEC-07

Read-only opens authorize destructive SDMMC operations

Observation permission incorrectly implied mutation permission
HighFixed

Issue

Erase, lock, write-protect, DSM, RPMB, raw commands, and driver-state changes passed when either _IO_FLAG_RD or _IO_FLAG_WR was present.

Remediation

Classify devctls by effect. Require read mode for pure queries, write mode for mutations, and inspect mixed command structures so GET remains readable while SET/CLEAR requires write access.

Why it works

A descriptor opened for observation can no longer erase, lock, alter, or issue raw commands. A device ACL/ability policy is still required as the second production layer and is not supplied by this BSP.

SEC-08

RPMB frame count bypasses message bounds

Zero or overflowing counts reach allocation, DMA, and frame access
HighFixed

Issue

A zero-frame READ satisfied a header-only size check, then wrote and transmitted a frame beyond the request. Large counts were multiplied repeatedly with inconsistent integer types.

Remediation

Require a nonzero count no greater than the 16-bit RPMB protocol maximum, accept only READ/WRITE/RL_WRITE and preserve normal-versus-reliable write semantics, compare count with trailing bytes by division, and use one checked transfer size in both SIM and SDIO layers.

Why it works

No frame pointer is derived until at least one complete frame exists. The 65,535-frame cap keeps count × 512 representable in the lower layer and consistent across copy, allocation, scatter/gather, and free.

SEC-09

Mailbox command-line object overlaps the loaded image

Fixed address 0x7ff80 + 512 bytes crosses IFS load address 0x80000
MediumFixed

Issue

The header reserved 128 bytes at 0x7ff80, but mbox_get_cmdline() overlaid a 512-byte message. Its last 384 bytes occupied the image loaded at 0x80000, causing deterministic early-boot corruption.

Remediation

Replace the hard-coded physical address with linker-owned, 16-byte-aligned, 512-byte storage; zero and size-check each message before sending it.

Why it works

The linker places the object as part of valid startup storage and its declared capacity matches the largest mailbox message, so initialization and firmware replies cannot cross into an unrelated image address.

SEC-11

FDT mapping and property parsing lack validation

Malformed DTB → oversized mappings, OOB reads, bad identity/RAM choice, or wrong interrupt
MediumMitigated

Issue

The generic and boot-option initializers trusted the declared total size too early and still receive a boot-supplied physical pointer. Bootargs were copied without a terminator, linux,revision was read without requiring four bytes, and serial stdout-path/interrupts parsing trusted unbounded strings and arbitrary interrupt tuples.

Remediation

Check the header address extent before mapping, validate the header before its total size, share a 16 MiB cap with checked physical extents, cap properties, add NUL termination, parse MAC/revision data exactly, and allow only the expected three-cell level-high debug UART IRQs. Require authenticated boot for pointer provenance.

Why it works

An untrusted size cannot create an oversized or wrapped mapping, string consumers receive bounded C strings, fixed-width properties must contain their declared type, and the DTB cannot redirect the console handler to an unrelated interrupt. Arithmetic checks cannot prove that an arbitrary physical pointer denotes trusted RAM, so boot authentication remains required.

SEC-13

I²C resource manager retains an unbounded client-sized buffer

Authorized request → persistent process memory pressure
MediumFixed

Issue

The driver allocated and retained a buffer sized to the largest send/receive request with no driver-level ceiling. One authorized client could permanently inflate the resource manager’s heap.

Remediation

Introduce an overrideable 64 KiB limit for each send or receive phase and reject larger requests with EMSGSIZE before allocation.

SEC-14

Local user → system-wide memory exhaustion
MediumDeployment required

Issue

C-01

SDMMC devctls trust truncated headers and weak range limits

Short CCB → conditional OOB access; oversized range lists → unbounded synchronous work
Conditional MediumFixed

Issue

CARD_REGISTER, write-protect, erase, and DSM paths inspected request fields before proving the fixed header existed. The card-register write consumed an unproved trailing byte. DSM checked its byte count only after reading nranges and had no documented 128-range work cap. Erase and write-protect narrowed 64-bit counts before validation.

Remediation

Validate every fixed header before dereference, compare trailing DSM records by division and cap them at the documented 128-range interoperability limit, require nonzero subtractively bounded partition-relative ranges, reject counts above the 32-bit lower-layer limit before narrowing, and require exactly one EXT_CSD write byte.

Why it works

Each field and trailing record is present before use, synchronous work is bounded, and lower layers receive only representable ranges contained by the selected partition. The subtractive geometry checks also preserve safety if nonzero partition offsets are introduced later.

C-04

Conditional MediumFixed

Issue

C-05

RP1 MSI-X state is shared across serial ports

Multiple UARTs in one process → unmask through the last port’s state
Conditional MediumFixed

Issue

The serial driver supports multiple devices, but RP1 MSI-X base/register variables were global. Each initialization overwrote them and every interrupt handler used the last values.

Remediation

Store the unmask mapping and register in each DEV_PL011, pass the device to variant_intr_unmask(), and resolve the FDT IRQ before selecting the register.

Why it works

Interrupt acknowledgement is now tied to the port that produced the interrupt; adding another UART cannot redirect an existing handler’s MMIO write.

C-06

Startup argument insertion has unsafe count and move arithmetic

Many/long boot tokens → out-of-object read/write
Conditional MediumFixed

Issue

The signed 8-bit argument count could wrap; traversal used unbounded strlen; expansion moved data from p - diff; and an 8 KiB mapping was treated as object capacity even though startup boot arguments shared a 3 KiB region with the live stack. Loaded bootstrap blocks had the same false spare-capacity assumption.

Remediation

Reserve a dedicated 8 KiB AArch64 startup boot-argument arena before the unchanged stack and derive its capacity from linker symbols. Scope growth permission to that owned object. Map loaded bootstrap arguments header-first and then to exactly their validated used size, making legacy or foreign blocks no-growth. Validate the complete advertised string list, reject invalid sizes/counts, bound every string walk, and move the correct tail.

Why it works

Positive growth occurs only when a caller supplies proven writable capacity. Startup insertion cannot reach the separate live stack; foreign blocks cannot grow into adjacent ELF data; and complete-list, count, traversal, and move checks prevent wrap or out-of-object access.
